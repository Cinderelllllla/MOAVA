# MOAVA | 모임 생성·가입·인증

> 담당 기능: F15, F16, F17, F18
> 모임 생성, 가입 신청 및 승인, 모임장 권한,
> 비공개 모임 초대 및 인증코드 관리
>
> 최종 수정일: 2026-11-25
>
> 본 문서는 해당 기능의 구현 범위를 설명하며,
> MOAVA 전체 기능의 구현 완료를 의미하지 않습니다.

## 3. F15 — 모임 생성

### 3.1 주요 기능

- 인증된 회원만 모임 생성 가능
- 요청 본문이 아닌 서버 인증 정보에서 회원 ID 추출
- 모임 기본 정보 및 필수 입력값 검증
- 생성자를 모임장 및 ACTIVE 상태의 모임원으로 등록
- SecureRandom 기반 32자리 16진수 초대 토큰 생성
- 예금주명 및 계좌번호 암호화
- 계좌번호 식별용 HMAC-SHA256 해시 생성
- 모임 생성 관련 DB 처리의 트랜잭션 관리
- 모임 생성 감사 로그 기록

### 3.2 입력값 검증

| 항목 | 검증 조건 |
| --- | --- |
| 모임명 | 필수 입력 |
| 목적 | 허용된 목적 코드 |
| 지역 | 시·도 및 시·군·구 |
| 월 납입액 | 5만 원 이상, 5만 원 단위 |
| 납입일 | 1~28일 |
| 최대 인원 | 2~30명 |
| 운영 기간 | 2~36개월 |
| 공개 여부 | PUBLIC / PRIVATE |
| 운영 규칙 | 필수 입력 |
| 모임 설명 | 필수 입력 |
| 모임 계좌 | 은행명 및 계좌번호 필수 |

### 3.3 모임 생성 처리 흐름

```text
React 모임 생성 화면
    ↓
POST /api/groups
    ↓
인증 회원 확인
    ↓
입력값 검증
    ↓
모임 ID 및 초대 토큰 생성
    ↓
GYE_GROUP 저장
    ↓
생성자 모임장 및 모임원 등록
    ↓
계좌 정보 암호화 및 저장
    ↓
감사 로그 기록
    ↓
HTTP 201 Created
```

모임 생성 과정의 DB 변경은 하나의 트랜잭션으로
처리하며, 롤백 동작은 통합 테스트를 통해 검증한다.

## 4. F16 — 모임 가입 및 승인

### 4.1 가입 신청 정책

- 인증된 일반 회원만 가입 신청 가능
- 모임장 본인의 중복 가입 신청 차단
- 이미 참여 중인 회원의 중복 가입 차단
- 자진 탈퇴 및 강제 탈퇴 회원의 동일 모임 재가입 차단
- 기존 가입 이력이 없는 거절·만료 신청자의 재신청 허용
- 승인 대기 중인 중복 신청 차단
- RECRUITING 상태의 모임만 가입 신청 가능
- 정원에 도달한 모임은 가입 신청 불가
- 비공개 모임은 인증코드 검증 완료 후 신청 가능
- 최종 가입 여부는 모임장의 승인으로 결정

### 4.2 가입 신청 상태

| 상태 | 설명 |
| --- | --- |
| PENDING | 모임장 승인 대기 |
| APPROVED | 가입 승인 완료 |
| REJECTED | 가입 거절 |
| EXPIRED | 신청 유효기간 경과로 만료 |

### 4.3 가입 신청 처리 흐름

```text
회원 가입 신청
    ↓
모임 상태 및 정원 확인
    ↓
기존 참여 여부 및 중복 신청 확인
    ↓
비공개 모임 인증 상태 확인
    ↓
JOIN_REQUEST 저장 (PENDING)
    ↓
모임장에게 가입 신청 알림 발송
    ↓
모임장 승인 또는 거절
    ├─ 승인: APPROVED 및 모임원 등록
    ├─ 거절: REJECTED
    └─ 7일 경과: EXPIRED
```

### 4.4 가입 신청 자동 만료

- 가입 신청 유효기간은 신청 시점부터 7일이다.
- 7일이 경과한 PENDING 신청은 승인 및 거절할 수 없다.
- 만료 대상은 승인 대기 목록에서 제외한다.
- 자동 만료 처리 시 상태를 EXPIRED로 변경한다.
- 시스템 처리이므로 DECIDED_BY는 NULL로 저장한다.
- DECIDED_AT에 만료 처리 시각을 기록한다.
- 신청 회원에게 만료 결과 알림을 발송한다.
- 자동 만료 배치는 기본적으로 1분마다 실행하도록 구성한다.
- DB 마이그레이션 적용 전에는 배치를 활성화하지 않는다.

### 4.5 자동 만료 배치 설정

설정 파일 또는 실행 환경에 다음 설정을 적용할 수 있다.

```properties
moava.group.join-request.expire.enabled=false
moava.group.join-request.expire.cron=0 * * * * *
```

| 설정 | 설명 |
| --- | --- |
| enabled | 자동 만료 배치 활성화 여부 |
| cron | 자동 만료 검사 실행 주기 |

배치는 DB 마이그레이션 적용 및 검증 완료 후
enabled 값을 true로 설정하여 활성화한다.

기본 실행 시간대는 Asia/Seoul이다.

### 4.6 모집 종료 정책

- 모임장을 포함한 현재 ACTIVE 참여 인원을 집계한다.
- 현재 참여 인원이 최대 인원에 도달하면 가입을 차단한다.
- 가입 신청 시점과 승인 시점에 각각 정원을 검증한다.
- 내 계모임 및 운영 홈에서 모집 종료 상태를 표시한다.
- 모집 종료는 화면 표시용 상태이며 별도의 DB 상태가 아니다.
- 정원 도달만으로 GYE_GROUP.STATUS를 ACTIVE로 변경하지 않는다.
- ACTIVE는 모임 운영이 시작된 상태를 의미한다.

### 4.7 탈퇴 회원 재가입 제한 정책

팀 협의 결과, 탈퇴가 완료된 회원은 동일 모임에 재가입할 수 없다.

| 회원 상태 | 가입 가능 여부 |
| --- | --- |
| 기존 가입 이력이 없는 회원 | 조건 충족 시 가능 |
| 가입 승인 대기 회원 | 중복 신청 불가 |
| 가입 신청 거절 회원 | 재신청 가능 |
| 가입 신청 만료 회원 | 재신청 가능 |
| ACTIVE | 가입 불가 |
| WITHDRAWN | 재가입 불가 |
| EXPELLED | 재가입 불가 |

- 모집 중 참여 취소 완료 회원도 동일 모임에 재가입할 수 없다.
- 곗돈 수령 후 특별 탈퇴한 회원도 재가입할 수 없다.
- 가입 신청 거절 및 만료는 실제 가입 이력이 없는 경우에만 재신청할 수 있다.
- 가입 신청 시점과 모임장 승인 시점에 기존 가입 이력을 모두 검사한다.
- GYE_MEMBER의 GROUP_ID 및 MEMBER_ID를 기준으로 기존 가입 이력을 조회한다.
- 기존 탈퇴 회원을 ACTIVE 상태로 재활성화하지 않는다.
- 탈퇴 처리 시 기존 GYE_MEMBER_ID와 회원 이력을 유지해야 한다.
- 재가입 제한 정책에 따른 추가 DDL 변경은 없다.

F29의 회차별 납입 및 정산 정책은 별도 구현 범위이며,
이번 F16 변경에서는 기존 F29 로직을 수정하지 않는다.

## 5. F17 — 모임장 권한

### 5.1 권한 정책

- 모임 생성자를 최초 모임장으로 등록한다.
- 모임장 여부는 서버에서 확인한다.
- 클라이언트의 버튼 표시 여부만으로 권한을 판단하지 않는다.
- 다른 모임의 관리 API에 접근할 수 없다.

### 5.2 모임장 관리 기능

- 참여 회원 목록 조회
- 가입 신청 목록 조회
- 가입 신청 승인 및 거절
- 비공개 모임 인증코드 발급 및 재발급
- 비공개 모임 초대 링크 조회

## 6. F18 — 비공개 모임 인증

### 6.1 초대 토큰과 인증코드 구분

| 구분 | 초대 토큰 | 인증코드 |
| --- | --- | --- |
| 형식 | 32자리 16진수 | 6자리 숫자 |
| 목적 | 초대 대상 모임 식별 | 비공개 모임 가입 인증 |
| 사용 위치 | 초대 링크 | 인증 입력 화면 |
| 재발급 | 인증코드 재발급과 별개 | 모임장 요청 시 |
| 관련 컬럼 | INVITE_CODE | JOIN_CODE_ENC |

초대 링크만으로 모임 가입이 승인되지 않는다.
비공개 모임은 인증코드 검증 및 모임장 승인이 필요하다.

### 6.2 인증 경로

```text
방식 A: 초대 링크

/invite?t={token}
    ↓
초대 대상 모임 조회
    ↓
6자리 인증코드 입력
    ↓
인증 성공
    ↓
가입 신청
    ↓
모임장 승인
```

```text
방식 B: 직접 입력

/invite
    ↓
모임 ID 입력
    ↓
6자리 인증코드 입력
    ↓
인증 성공
    ↓
가입 신청
    ↓
모임장 승인
```

### 6.3 인증 실패 제한 정책

- 인증 실패 횟수는 모임별·회원별로 관리한다.
- 최대 인증 실패 횟수는 3회이다.
- 3회 실패 시 인증을 차단한다.
- 기존 15분 경과 후 잠금 해제 정책은 사용하지 않는다.
- 시간 경과만으로 인증 제한이 해제되지 않는다.
- 모임장이 인증코드를 재발급해야 다시 인증할 수 있다.
- 다른 회원의 인증 실패 횟수에는 영향을 주지 않는다.
- 새로고침 시 서버에서 인증 상태를 다시 조회한다.
- 인증 상태 조회는 실패 횟수를 증가시키지 않는다.

### 6.4 인증 응답 상태

| 상태 | 설명 |
| --- | --- |
| READY | 인증 가능 |
| VERIFIED | 인증 성공 |
| ALREADY_VERIFIED | 기존 인증 완료 |
| INVALID_CODE | 인증코드 불일치 |
| LOCKED | 인증 실패 3회로 차단 |

### 6.5 인증코드 재발급

- 비공개 모임의 모임장만 재발급할 수 있다.
- 기존 인증코드와 다른 6자리 숫자를 생성한다.
- 인증코드는 암호화하여 저장한다.
- 재발급 시 JOIN_CODE_VERSION을 증가시킨다.
- 이전 버전의 인증 상태 및 실패 횟수는 무효화한다.
- 회원의 다음 인증 상태 조회 또는 인증 요청 시
  현재 코드 버전에 맞게 인증 기록을 초기화한다.
- 기존 초대 링크 토큰은 유지한다.
- 이미 제출된 가입 신청의 인증 확인 기록은 유지한다.

### 6.6 인증 실패 및 재발급 흐름

```text
인증 가능 (남은 횟수 3회)
    ↓ 실패
남은 횟수 2회
    ↓ 실패
남은 횟수 1회
    ↓ 실패
LOCKED
    ↓
모임장 인증코드 재발급
    ↓
코드 버전 변경
    ↓
회원 인증 상태 초기화
    ↓
인증 가능 (남은 횟수 3회)
```

## 7. 프론트엔드 연동

### 7.1 주요 화면

| 화면 | 경로 |
| --- | --- |
| 모임 생성 | /groups/new |
| 내 계모임 | /my-groups |
| 운영 홈 | /operations |
| 인증코드 직접 입력 | /invite |
| 모임 ID 지정 인증 | /invite?groupId={groupId} |
| 초대 링크 | /invite?t={token} |

### 7.2 내 계모임

- 본인이 모임장이거나 ACTIVE 모임원인 모임 조회
- 현재 참여 인원 및 최대 인원 표시
- 모집 중, 모집 종료, 운영 중 등의 상태 표시
- 모임 정보 조회
- 운영 홈 이동
- 관리 기능은 운영 홈으로 분리

### 7.3 운영 홈

선택한 모임의 정보를 다음 세 영역으로 구분한다.

1. 모임 운영 상태
2. 모임 관리 기능
3. 모임 기본 정보

모임장 관리 기능은 모임장에게만 표시한다.
비공개 모임 전용 기능은 공개 여부에 따라 구분한다.

### 7.4 가입 신청 알림

모임장이 가입 신청 알림을 선택하면
해당 모임의 운영 홈 및 가입 신청 관리 영역으로 이동한다.

```text
/operations?groupId={groupId}&tab=joinRequests
```

기존 내 계모임 기반 알림 경로는
운영 홈으로 이동하도록 호환 처리를 유지한다.

## 8. 주요 API

| Method | Endpoint | 설명 |
| --- | --- | --- |
| POST | /api/groups | 모임 생성 |
| GET | /api/groups/my | 내 계모임 조회 |
| POST | /api/groups/{groupId}/join-requests | 가입 신청 |
| GET | /api/groups/{groupId}/join-requests | 가입 신청 목록 |
| POST | /api/groups/{groupId}/join-code | 인증코드 발급·재발급 |
| POST | /api/groups/{groupId}/join-code/verify | 인증코드 검증 |
| GET | /api/groups/{groupId}/join-code/verification-state | 인증 상태 조회 |
| GET | /api/groups/{groupId}/invite | 모임장 초대 토큰 조회 |
| GET | /api/v1/invites/{token} | 초대 대상 모임 조회 |

가입 승인·거절 및 참여 회원 조회의 상세 경로와
요청·응답 형식은 해당 Controller 및 DTO를 기준으로 한다.

### 8.1 가입 신청 요청 예시

```http
POST /api/groups/13/join-requests
Content-Type: application/json
Authorization: Bearer {accessToken}
```

### 9.2 DB 마이그레이션

신규 설치용 DDL:

```text
infra/sql/01_moava_ddl.sql
```

기존 DB 변경용 마이그레이션:

```text
infra/sql/05_moava_join_policy_migration.sql
```

주요 변경 사항:

- JOIN_CODE_ATTEMPT.FAIL_COUNT 허용 범위 0~3
- 기존 시간 기반 인증 잠금 정책 제거
- LOCKED_UNTIL 컬럼은 기존 DB 호환성을 위해 유지
- JOIN_REQUEST.STATUS에 EXPIRED 추가
- 관련 제약조건 및 컬럼 설명 변경

기존 DB에 마이그레이션을 적용하기 전
데이터 및 제약조건을 확인해야 한다.

Oracle DDL은 암시적 COMMIT이 발생하므로
공용 DB 적용은 팀 협의 및 백업 이후 진행한다.
