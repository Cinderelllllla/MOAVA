# MOA-98 위험 등급을 자가 응답 4문항 기반으로 변경 — 변경 요약·명세서 정정안

## 왜 바꿨나
- 기존 위험 등급은 회원 번호로 무작위 연결한 가상 인물(`persona_scores.csv`) 점수였다. 가입자 본인과 관계가 없었다.
- 기존 모델(지표 189개)은 `CB`(교육용 위험등급, NICE 등급 아님) 컬럼에 약 70% 의존해서, 사용자에게 물어볼 수 있는 지표만으로는 쓸 수 없었다.
- 그래서 사용자가 직접 답할 수 있는 4문항으로 작은 모델을 새로 학습했다. 합성 데이터로 학습한 **교육용 모델**이며 실제 신용평가가 아니다.

## 결과 (테스트 31,150명)
| | 자가 응답 4문항 | 기존 189개 지표 |
| --- | --- | --- |
| ROC-AUC | 0.622 | 0.664 |
| 등급 분포 (안정/주의/위험) | 74% / 23% / 3% | 77% / 17% / 6% |
| 등급별 실제 연체율 | 7% / 14% / 35% | 7% / 15% / 35% |

## 바뀐 흐름
1. 맞춤 추천 1단계: 금액 6개 + **신용 관련 질문 4개**(선택형) + 동의 → 모두 필수
2. 프론트 → `POST /api/v1/finance/ai/contribution` 에 `self_report` 4문항 포함
3. Spring: 4문항 검사(없거나 목록 밖이면 400 `INVALID_SELF_REPORT`) → ML `/risk/contribution` 에 `self_report` 전달 (`member_id` 는 보내지 않음)
4. ML: 4문항 모델로 연체 확률 → 등급(안정/주의/위험)·안전계수 → 추천 납입액
5. Spring: 결과를 `RISK_SCORE`(확률·등급·안전계수)에 저장, 화면에는 등급·안전계수만 응답
6. **4문항 원본은 DB·로그·브라우저 저장소에 남기지 않는다.** 다시 분석하려면 1단계에서 다시 답한다.

화면: 2단계(소비 분석)에서는 위험 등급 표시를 뺐다(월수입·월지출·남는 돈 카드 3개만, S03 ②).
3단계와 `/finance` 위험 등급 패널에 "입력하신 신용 답변 기준 · 교육용 모델" 문구와 추천액 계산 과정을 표시한다.
"기존 저축액" → "월 저축액" (계산식에서 매달 빠지는 금액이므로).

## 기능명세서 정정안 (팀장 확인 후 반영)
| 항목 | 현재 | 변경안 |
| --- | --- | --- |
| F05 입력 항목 | 월수입·고정/변동지출·기존 저축액·비상예비금·희망 월 납입액 | "기존 저축액" → **월 저축액**. 신용 관련 자가 응답 4문항 추가(최근 1년 30일 이상 연체 횟수 / 최근 6개월 최장 연체 기간 / 상환 중 대출 수 / 카드 한도 사용률). 4문항은 저장하지 않음 |
| F09 입력값 | `MEMBER.SYN_ID`(가상 신용 ID) | **자가 응답 4문항** (교육용 모델, ROC-AUC 0.622) |
| F09 "RISK_SCORE 저장 미구현" | 미구현으로 기재 | **이미 구현됨** — `FinanceProfileService.recordRiskScore` 가 분석 성공 시 INSERT |
| F27 수령 순서 | 분석 기록 없는 회원은 기본값 0.35 로 계산 | 0.35 는 '주의' 안전계수였음 → **분석 기록 없는 회원은 맨 뒤 회차**, 화면에 "AI 분석 전" 표시 |
| F11 모임 건강도 | 분석 기록 없는 회원은 0.20 으로 계산 | 0.20 은 '위험' 안전계수였음 → **분석 기록 있는 회원만 평균** |

## 결정: 분석 기록이 없는 모임원 (담당 팀원 확인 완료)
`PayoutOrderMapper.xml`(수령 순서 AI 제안 회차)은 `NVL(rs.PROB, 0.35)`,
`GroupQueryMapper.xml`(모임 건강도 F11)은 `NVL(RS.PROB, 0.20)` 을 써서 안전계수 값이 연체 확률 자리에 들어가 있었다.

- **수령 순서(F27)**: 분석 기록이 없는 회원은 **맨 뒤 회차**로 보낸다. 기록이 있는 회원끼리는 연체 확률이 높은 순(동률이면 회원 번호 순).
  최신 기록은 `SCORED_AT DESC, RISK_SCORE_ID DESC` 로 고른다.
- **모임 건강도(F11)**: **분석 기록이 있는 회원만** 평균한다. 아무도 없으면 서비스 기본 점수(`DEFAULT_HEALTH_SCORE`).
- 수령 순서 신청 목록에 `aiAnalyzed`(신청자의 분석 기록 유무, 조회 시점 기준)를 추가하고, 없으면 화면에 "AI 분석 전" 표시.
